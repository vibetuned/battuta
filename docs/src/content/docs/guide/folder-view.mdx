Most editing sessions are not one file: they are a folder of movements, a
set of exercises, a directory someone sent you. The folder view puts that
folder down the left of the window — the score moves over to make room,
it is never covered — so opening the next score is a click instead of a
dialog.

Click the **📁** in the header to show or hide it; the panel's **×** does
the same.

<Aside type="caution" title="The desktop app and tablets">
A browser tab cannot be handed a folder to read, so in the web editor the
panel opens and says so. Everything else in battuta works there.

On an iPad or an Android tablet the panel opens on **battuta's own
folder** — where it saves your scores ([on a tablet](../files/#on-a-tablet)),
shown as *battuta* — with nothing to choose. **…** opens the system's
folder picker for any other folder: Files and iCloud Drive on an iPad, the
tablet's storage and your cloud drives on Android. battuta keeps access to
the folder you pick and reopens it next time; **⌂** takes you back to its
own. Renaming and the two **+** buttons work in any of them; the list does
not refresh by itself when another app changes the folder (reopen the
panel).
</Aside>

## Opening a folder

**choose a folder…** asks the system for one. battuta can read **that
folder and nothing else** — there is no general file access behind this,
and every read outside the folder you picked is refused. Pick another one
any time with the **…** button beside its name.

The folder you opened is remembered, so it is there the next time you
start battuta. If it has moved or been deleted since, the panel says so
and offers to pick another.

## The list

Sub-folders open in place — click one to expand it, click again to
collapse — so a folder with a directory per work behaves the way you
expect. Hidden files and folders are skipped.

Click a score to open it. It opens exactly as **open file…** would: a
file already open is brought to the front rather than opened twice, and a
format that needs [converting](../files/#opening-other-formats) converts
on the way in.

| Mark | Means |
| --- | --- |
| highlighted row | the score in the active tab |
| trailing `*` | open, with unsaved changes — the same marker the tab shows |

<Aside type="note" title="Which files are listed">
The panel lists **`.mei`** scores and folders — it is a view of MEI
scores. battuta opens MusicXML, ABC, Plaine & Easie and Humdrum too:
open those with **open file…** and they become MEI tabs, which the view
then shows.
</Aside>

## Renaming

Point at a score or a folder and a **✎** appears at the end of its row;
click it — or select the row and press <kbd>F2</kbd> — and the name
becomes a field. Type the new one and press <kbd>Enter</kbd>, or click
away; <kbd>Esc</kbd> leaves it as it was.

A score is renamed **without its extension**: the field shows the name the
list shows, and `.mei` is kept for you. A folder is renamed as typed, and
if it was open it stays open under its new name.

If the score is open in a tab, the tab follows: it takes the new name and
saves to the renamed file — nothing is written to the old name behind
your back. A name that already exists in the folder, an empty one, one
with a `/` in it or one starting with a dot (it would be hidden) is
refused, and a notice says why.

## New scores and folders

**+ score** and **+ folder** in the panel's header create inside the
**folder you last clicked** — or the folder of the score you last opened,
or the top folder until you have done either. That folder is **marked** —
a blue bar at the left of its row, or beside the folder's name at the top
of the panel when it is the top folder — and hovering a button names it. A field appears first inside it: type a name and press
<kbd>Enter</kbd>, or click away; <kbd>Esc</kbd> changes nothing.

A new score is a blank one — a treble staff in 4/4, four empty measures,
titled after its name — saved as `.mei` (added for you) and **opened at
once in a new tab**, ready to write in. A new folder appears open and
empty, and becomes where the next score goes, so a folder of new pieces
is **+ folder**, a name, then **+ score** as many times as you need.

A name that already exists is refused — nothing is ever overwritten — as
are the names renaming refuses.

<Aside type="note" title="New after 1.0.0">
Renaming and creating are the folder view's only changes to your disk,
and they stay inside the folder you opened: that folder itself cannot be
renamed from here, nothing is overwritten, moved between folders or
deleted.
</Aside>

## Live file watching

While the panel is up, battuta watches the folder. A score added,
renamed or deleted — by you in another program, by a sync client, by a
`git pull` — appears or disappears in the list without a refresh.

The same watch protects what you have open. If a file open in a tab
changes on disk, battuta tells you **the moment it happens**:

> "two.mei" changed on disk — saving will ask before overwriting

Saving still asks for confirmation before it overwrites, as it always
did; the difference is that you now hear about the change while you can
still do something about it, rather than at the moment you save.

## Turning it off

battuta menu → **🌣 shortcuts** → **plugins** → *Folder view*. The 📁 and
the panel go together, and battuta stops watching. Nothing about your
scores changes — apart from the names you gave and the scores and folders
you made, the folder view only ever reads.
