battuta is a desktop application. It reads and writes MEI files on your own
disk, needs no account, and makes no network requests — nothing you open
leaves your machine.

## Download a build

Bundles are attached to each [GitHub release](https://github.com/vibetuned/battuta/releases).

<Tabs>
  <TabItem label="Linux" icon="linux">

On Debian/Ubuntu, the apt repository keeps you updated with the system:

```sh
sudo curl -fsSL https://battuta.vibetuned.com/apt/battuta.asc -o /etc/apt/keyrings/battuta.asc
echo "deb [signed-by=/etc/apt/keyrings/battuta.asc] https://battuta.vibetuned.com/apt stable main" | sudo tee /etc/apt/sources.list.d/battuta.list
sudo apt update && sudo apt install battuta
```

Or grab a bundle directly — two flavours, both 64-bit x86:

- **`battuta_<version>_amd64.deb`** — the small one (~6 MB); it uses the
  WebKitGTK already on your system.
  ```sh
  sudo apt install ./battuta_0.0.1_amd64.deb
  ```
- **`battuta_<version>_amd64.AppImage`** — self-contained (~81 MB, WebKitGTK
  bundled); no install step.
  ```sh
  chmod +x battuta_0.0.1_amd64.AppImage
  ./battuta_0.0.1_amd64.AppImage
  ```

MIDI input goes through ALSA. The `.deb` declares that dependency, so it comes
in with the package; if you use the AppImage on a minimal system and the status
bar never finds your keyboard, install your distribution's ALSA runtime.

  </TabItem>
  <TabItem label="macOS" icon="apple">

With [Homebrew](https://brew.sh):

```sh
brew install --cask vibetuned/tap/battuta
```

Or download the `.dmg`, open it, drag battuta to Applications. One universal
binary covers Apple Silicon and Intel.

From **0.0.2** the app is signed with Vibetuned's Apple Developer ID and
notarized — no Gatekeeper hoops. (The old 0.0.1 image was unsigned; if you're
stuck on it, use Finder's context menu → *Open* the first time.)

Verified on Apple Silicon: the app launches, `.mei` files open by
double-click, and MIDI keyboards hot-plug through CoreMIDI.

  </TabItem>
  <TabItem label="Windows" icon="seti:windows">

Download the NSIS installer (`battuta_<version>_x64-setup.exe`). It
bootstraps Microsoft's WebView2 runtime if the machine doesn't have it.

The installer is **not Authenticode-signed yet**, so SmartScreen warns about
an unknown publisher the first time: choose *More info* → *Run anyway*.
(Free code signing for open-source projects is in the works.)

Verified on Windows 11: the installer completes and the editor runs.

  </TabItem>
</Tabs>

### Opening `.mei` files by double-click

The Linux packages register `*.mei` as `application/x-mei+xml` and hand the
clicked file to battuta, so double-clicking a score in your file manager opens
it in a new tab. macOS does the same through the app bundle, and the Windows
installer registers the same association in the registry. If a file manager
still opens `.mei` in a text editor, set battuta as the default application for
the type once — the association is registered, the preference is yours.

## Run from source

Useful for trying the editor without installing anything: the frontend is a
plain web app and runs in any modern browser (Chromium and Firefox both work;
Web MIDI needs Chromium).

<Steps>

1. Get the sources and dependencies — Node 22 or newer:

   ```sh
   git clone https://github.com/vibetuned/battuta.git
   cd battuta
   npm install
   ```

2. Start the editor:

   ```sh
   npm run dev --workspace @battuta/editor
   ```

3. Open the printed URL. In a browser, *open file…* and <kbd>ctrl</kbd> +
   <kbd>s</kbd> fall back to a file picker and a download instead of native
   dialogs; everything else behaves the same.

</Steps>

### Building the desktop shell

The desktop app is [Tauri 2](https://tauri.app/), so building it needs
[Rust](https://rustup.rs/) alongside Node, plus your platform's webview
toolchain. Tauri cannot cross-compile — a Windows installer has to be built
on Windows, a macOS bundle on macOS.

<Tabs>
  <TabItem label="Linux" icon="linux">

On Debian/Ubuntu:

```sh
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libasound2-dev \
  librsvg2-dev build-essential curl wget file libssl-dev
```

  </TabItem>
  <TabItem label="macOS" icon="apple">

The Xcode command line tools supply the toolchain:

```sh
xcode-select --install
```

For a universal binary, add both targets and build with
`npx tauri build --target universal-apple-darwin`:

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

  </TabItem>
  <TabItem label="Windows" icon="seti:windows">

Rust must be the **MSVC** toolchain — `rustup`'s default on Windows
(`x86_64-pc-windows-msvc`). Two more pieces:

- **Visual Studio Build Tools** with the *Desktop development with C++*
  workload, which supplies `link.exe` and the Windows SDK. A full Visual
  Studio Community install with that workload works equally well.
- **The WebView2 runtime**, already present on Windows 11 and current
  Windows 10. (The shipped installer bootstraps it; a source build expects
  it to be there.)

No shell-specific setup is needed — PowerShell, cmd and Git Bash all work.

  </TabItem>
</Tabs>

Then, from the repository root (one command per line — `&&` is not valid in
Windows PowerShell 5):

```sh
npm install
cd apps/editor
npx tauri build
```

`tauri build` builds the frontend first, and that in turn builds
`@battuta/core`, so there is no separate frontend step to remember. The
bundles land in `apps/editor/src-tauri/target/release/bundle/`: a `.deb` and
an `.AppImage` on Linux, a `.dmg` on macOS, an NSIS `-setup.exe` on Windows.
(A universal macOS build writes to
`target/universal-apple-darwin/release/bundle/` instead — per-target builds
get their own directory.)
The binary prints at startup whether it is serving embedded assets or talking
to the dev server, so you always know which one you launched.
